# Arabic Skills Control Center Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make the AIRI Skills experience fully compliant with the selected Arabic language, RTL-aware, modern, and centered on safe activation, prompt shortcuts, and developer-grade execution transparency without changing skill runtime identifiers or permissions.

**Architecture:** Keep `SkillManifest` and `SkillRegistry` as the source of executable truth. Add a presentation-layer localization catalog keyed by stable skill IDs, then make the manager, detail screen, community surface, and composer suggestions consume localized display data while retaining English-safe IDs such as `/skill:research_agent`. Redesign the detail surface as an AIRI dark control center: hero summary, prompt examples, activation CTA, explanation CTA, and explicit security/execution metadata.

**Tech Stack:** Kotlin, Jetpack Compose Material 3, Android resources (`values-ar`/`values`), existing AIRI theme, JVM unit tests, Gradle Android CI.

**Spec:** User request dated 2026-09-25; official comparison sources: `https://manus.im/docs/features/skills`, `https://manus.im/features/agent-skills`, and `https://help.manus.im/en/articles/14753565-how-to-share-and-use-skills-in-manus`.

## Global Constraints

- Arabic UI copy must be loaded through Android resources or the localization catalog; no user-facing English fallback is allowed when Arabic is selected.
- Stable IDs, slash directives, connector IDs, model access values, memory access values, permissions, and risk levels remain unchanged.
- The Try action must prefill the existing composer with `/skill:<stable_id> ` and must not execute or send a message automatically.
- Explanation requests must be Arabic when Arabic is selected and must preserve the existing safe, non-destructive intent.
- Skill cards and details must expose security/execution facts, not merely marketplace marketing copy.
- Interactive controls need accessible labels, adequate touch targets, logical RTL order, and readable contrast.
- Do not fabricate 74 skills: render every entry returned by the canonical catalog and add a regression count test matching the repository’s actual catalog contract.

## Review Focus

- A localized display name must never replace the stable ID used by `/skill:` routing; test the exact directive generated by Try.
- Search must match Arabic display text as well as English metadata and stable IDs; test Arabic query against a catalog entry.
- Connector-gated skills must remain visibly unavailable and cannot be enabled until the connector is present; test the existing registry behavior through the new CTA.
- Permissions, memory access, model access, risk, confirmation, streaming, and attachment metadata must remain truthful after localization; test representative low/medium/high-risk entries.
- Empty examples, unknown categories, and legacy manifests must render safely without English UI leakage; test normalized fallback behavior.

## Official design comparison

Manus documents Skills as discoverable from a Skills tab, addable through an Add menu, and invokable from the chat input with `/`. The same documentation emphasizes progressive disclosure and reviewing community skills for security. AIRI’s differentiator is stronger runtime transparency: memory access, model access, permissions, connector availability, risk, confirmation, and execution capabilities remain visible in the detail view. The implementation therefore borrows Manus’s low-friction discovery and slash-command shortcut while preserving AIRI’s developer control center rather than turning the screen into a purely consumer marketplace.
