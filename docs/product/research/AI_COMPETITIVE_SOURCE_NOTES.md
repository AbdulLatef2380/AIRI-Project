## Research rules

1. Product pages describe vendor positioning, not independently verified performance or customer willingness to pay.
2. Any final commercial comparison must cite the specific original pages and date of access.
3. AIRI's value claims must be backed by its own runtime, tests, device validation and user research; a competitor feature list is not an implementation roadmap.

| Claude | [Claude Platform Features Overview](https://platform.claude.com/docs/en/build-with-claude/overview) | The official platform documentation separates model capabilities, tools, tool infrastructure, context management and files/assets. It documents structured outputs, citations, context controls, web search/fetch, code execution, browser/computer tools, memory and text editing, each with availability qualifiers. | AIRI should not equate its source model integration with an agent platform. Its product contract must independently own tool authority, privacy, side effects, evidence and recovery. These are the relevant differentiators for its local-first mobile scope. |

## Additional sourcing note

The Claude product page also describes desktop/mobile availability, connectors, scheduling and cross-device task checking. These are competitive expectations, not proof that an early Android product must ship those surfaces. AIRI should select only the small subset that improves its first persona's weekly workflow and prove it under local-first constraints.
