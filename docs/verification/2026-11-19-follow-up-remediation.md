# AIRI — Follow-up Remediation and Verification

**Date:** 2026-11-19  
**Branch:** `main`  
**Scope:** Review of the user-provided production-readiness concerns against the checked-out source. This report distinguishes source inspection from executable verification.

## Changes made in this follow-up

- **Concurrent tool idempotency:** `ToolExecutionPipeline` now coordinates in-flight executions by `RequestId`; concurrent duplicate requests await the same result instead of racing past the result ledger. Added a concurrency regression test.
- **Imported skill permissions:** `permissions` from GitHub manifests are now retained in `CustomSkill`, passed by the importer and dynamic registration path, and exposed by `CustomSkillAiriSkillAdapter.requiredPermissions` so the existing access policy can fail closed when a permission is not granted. The new field is nullable for compatibility with old Gson-persisted records.
- **GenUI card actions:** card action callbacks are rebuilt from the original assistant message and use the card's source-authored body; arbitrary callback fields are ignored. The renderer now marks the action `STAGED`, not `SUCCEEDED`, before the ViewModel has accepted it. Added a compiler regression test.
- **GenUI images:** the schema accepts only HTTPS image sources without embedded user information, and the renderer uses Coil `AsyncImage` to display them rather than printing the source URL as text. Added a parser regression test for HTTPS acceptance and `file:` rejection.
- **Secret Manager biometric gate:** entering the screen now requests biometric/device-credential authentication before loading API keys or showing the management list. Failed, unavailable, or unsupported authentication no longer silently succeeds; edit/delete/copy operations are also gated.
- **Secret Manager lifecycle:** moving the app to `ON_STOP` now locks the screen, clears visible secret text/dialog state, and ignores a biometric callback if the activity is no longer resumed. This remains unverified on a device.
- **Profile photo replacement:** the existing UID-scoped local photo upload is implemented; replacement now preserves the previous file in a temporary backup until the new file has been moved successfully, attempts restoration on failure, and checks that the authenticated UID has not changed before saving the picker result.
- **Marketplace skill import:** redirects are disabled, fetched definition URLs and execution endpoints must pass HTTPS/public-host/no-credentials policy, DNS resolution rejects private hosts, and response bodies are bounded while streaming. Added policy regression tests; they have not run in this sandbox.
- **Theme surfaces:** three neutral surface backgrounds in `ModelSettingsScreen` were changed to `AiriTheme.surfaceVariant`; this is a limited code change, not a visual audit.
- **GenUI state ownership:** `ChatScreen` now passes its `GenerativeUiStateStore` into `ChatMessageList` rather than referencing an out-of-scope `viewModel`.
- **Theme references and stale reports:** 47 direct `MaterialTheme.colorScheme` references in app UI sources were changed to `AiriTheme.colorScheme`, which resolves to the active Material color scheme. Historical color-refinement and verification reports now explicitly warn that their results are not a current visual/build verification.

## Findings not closed by this follow-up

- **Memory path:** the production chat path adds one scoped `RagRetriever.buildContextBlock()` to the system prompt. Long-term extraction and durable persistence run through `MemoryManager`; accepted summaries use `MemoryStore` for coverage/state. The separate `MemoryStore.mergeFacts`/`PromptCompressor.compose` facts path has no production caller. Direct unit coverage was added for the pure `MemoryExtractor` (English/Arabic extraction and oversized-input rejection), alongside existing intent/admission/RAG-policy tests; these still do not prove extraction → durable storage → retrieval → final prompt end to end. I did not wire a duplicate prompt path because that could duplicate memory or bypass scope/privacy filters.
- **Planner, AgentLoop, and multi-tool model behavior:** source review found real `ChatViewModel` wiring through `AgentLoop`/`ToolDispatcher`, and existing vertical tests for read-only tool batches and result history. A new scripted vertical test now exercises two successive (non-batched) calls and asserts that the first tool result is present in the next model request; it does not prove a live model will choose those calls. The test has not run because local Gradle configuration lacks `javac`. A live-model/device scenario remains unverified; `ToolExecutionPipeline` also serves a distinct coding-agent path rather than being the direct AgentLoop dispatcher.
- **Theme literals:** direct `MaterialTheme.colorScheme` usage was normalized, but numerous hard-coded literals remain. Some are brand/status colors; some may still be surfaces or text. A semantic inventory plus light/dark/AMOLED screenshot or device review is still required before claiming full color-system unification.
- **Skill isolation:** permission propagation and marketplace network hardening reduce risk, but they are not OS-level isolation. Imported skills are HTTP-backed manifest-defined requests, not locally executed manifest code; first-party skills run in-process. Treat user-controlled remote endpoints and app-granted capabilities as a trust boundary. Do not claim a kernel-enforced process/UID sandbox or protection from arbitrary in-process code.
- **Full-screen biometric coverage:** content/key loading are UI-gated and `ON_STOP` now relocks, but this is not a hardware-backed cryptographic policy for every secret-store read. Navigation recreation, background/foreground behavior, alternate read paths, and biometric flow still need on-device verification.
