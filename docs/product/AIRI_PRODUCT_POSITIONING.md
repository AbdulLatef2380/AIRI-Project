# تموضع AIRI وقرار المستخدم الأول

> **الحالة:** `HYPOTHESIS_TO_VALIDATE`. هذه وثيقة قرار منتج، وليست دليلاً على طلب سوقي أو توقع إيراد أو تكافؤ مع أي منتج منافس.

## القرار التنفيذي

لا يستطيع AIRI في وضعه الحالي منافسة ChatGPT أو Gemini أو Claude أو Replit أو Manus بوصفه بديلاً عاماً متعدد المنصات. تلك المنتجات تعرض سعة نماذج، خدمات سحابية، أدوات، أو تكاملات واسعة؛ ولا يثبت وجود واجهة أو موصل أو نموذج محلي في AIRI التكافؤ معها. ChatGPT يعرض مسارات Chat وWork وCodex، بما في ذلك توصيل التطبيقات وتسليم مخرجات العمل [1]. وتعرض Gemini قدرات Live وDeep Research وخدمات Google وخيارات متغيرة بحسب المنطقة والخطة [2]. كما توثق منصة Claude أدوات وسياقاً وإدارة ملفات وبنى تشغيل أدوات ذات شروط توفر مستقلة [3]، ويعرّف Replit Agent نفسه كمنشئ تطبيقات ومخرجات متعددة من الوصف الطبيعي [4].

قرار AIRI هو عدم سباق هذه المنتجات في العدد أو السحابة، بل بناء **مساحة عمل ذكاء شخصية خاصة للمشاريع طويلة العمر على Android**. القيمة المقترحة هي: أن المستخدم لا يعيد شرح مشروعه، ويرى ما حُفظ ولماذا، ويعرف ما الذي سيفعله الوكيل، ويوافق على العملية المحددة قبل أثرها، ثم يعود إلى نفس المهمة مع دليل وحدود تعافٍ صريحة.

| سؤال | قرار AIRI | ما لا يدعيه القرار |
|---|---|---|
| من هو المستخدم الأول؟ | فرضية البداية: مطور Android مستقل أو صانع مشروع فردي يعمل من هاتفه ويحتاج متابعة ملفات، سياق، قرارات، ومهام مشروع متعددة الجلسات. | لا تدعي الوثيقة أن هذه الشريحة دُفعت أو تحققت؛ يلزم بحث مستخدمين. |
| ما الـJob-to-be-Done؟ | “عندما أعود إلى مشروع على هاتفي، أريد أن أفهم وضعه بسرعة، أسترجع موارده المسموح بها، وأكمل خطوة واضحة بموافقة وأثر يمكن مراجعته.” | لا تستبدل AIRI IDE أو منصة استضافة أو فريقاً كاملاً. |
| لماذا قد يبقى المستخدم؟ | تقليل إعادة الشرح وفقد القرار مع زيادة الثقة في ما ينفذ محلياً. | لا يكفي وجود chat أو ذاكرة وحده لإثبات retention. |
| ما الوعد الفريد؟ | **Private Project Continuity**: سياق مشروع مقيد، ذاكرة قابلة للتفسير، تنفيذ مقترح وموافق عليه، ودليل/تعافٍ. | لا يوعد بتشغيل متصفح موثوق، تحكم سطح مكتب، أو تنفيذ خارجي تلقائي عام. |

## المقارنة العملية

| المنتج/الفئة | ما يتوقعه المستخدم منه اليوم | أين لا ينافس AIRI | فرصة AIRI القابلة للدفاع |
|---|---|---|---|
| ChatGPT | محادثة عامة، كتابة، بحث، صوت، مخرجات عمل، وتطبيقات متصلة [1]. | عرض النموذج العام وسرعة التوسع السحابي. | مهمة مشروع محلية لها owner/evidence/recovery بدلاً من محادثة منفصلة عن حالة المشروع. |
| Gemini | مساعد متعدد الوسائط وخدمات Google ومزايا agent/brief متغيرة حسب الخطة والمنطقة [2]. | تكامل Google واسع أو وصول موحد للخدمات. | عدم افتراض مشاركة بيانات المشروع أو النشاط الشخصي مع حساب سحابي؛ سياق/موافقة محددان بالمشروع. |
| Claude | أدوات، ذاكرة، سياق كبير، structured outputs، بحث/جلب وتنفيذ/تحكم ضمن بيئات ومنصات موصوفة [3]. | بنية أدوات مزود عام أو مقياس سياق/سحابة. | حدود أندرويد محلية يمكن فحصها: no generic side effect، one typed proposal، claim-once، artifact evidence. |
| Replit | توليد تطبيقات ومخرجات متعددة من وصف طبيعي [4]. | بناء/نشر سحابي وتعاون واستضافة. | رفيق مشروع Android يعمل قبل/بعد بيئة التطوير، لا بديل سحابي لها. |
| Manus | التنفيذ الوكيلي واسع الأدوات هو مرجع تجربة مهم، لكن الصفحة الرسمية كانت غير متاحة لعرض قدراتها عند جمع المراجع، لذلك لا تقدم هذه الوثيقة مقارنة claim-by-claim [5]. | حوسبة/تحكم سحابي عام أو تشابه واجهة. | شفافية التحكم المحلي والموافقة والدليل، وليس تقليد واجهات المنصة أو ادعاء Cloud Computer. |

## موضع المنتج وصوته

> **AIRI يتذكر مشروعك بحدود واضحة، يشرح ما يعرفه، ويطلب موافقتك قبل أن يتصرف.**

هذا ليس شعاراً تسويقياً فقط. كل كلمة تقابل شرطاً هندسياً:

| الوعد | الإلزام البرمجي |
|---|---|
| يتذكر | scoped memory وProject Context؛ عرض سبب/مصدر/نطاق الذاكرة، تعديل وحذف، وعدم تسجيل رسائل عشوائياً كحقائق دائمة. |
| بحدود واضحة | project/session/privacy/expiry filtering قبل RAG، ورفض cross-project reads. |
| يشرح | Plan Board وExecution Center من `DurableTask` الحي، لا progress أو اقتراحات مصطنعة. |
| يطلب موافقتك | descriptor typed خاص بكل side effect، private review عند الحاجة، pause/claim once، وDeny/expiry cleanup. |
| يتصرف | لا generic dispatcher أو automated replay؛ كل runtime يملك العقد والاختبارات والدليل المناسب. |

## قرار نطاق 90 يوماً

| يبنى أولاً | سبب القرار | شرط الإغلاق |
|---|---|---|
| Project Home | يجمع قيمة AIRI في موضع واحد ويقلل البحث بين الشاشات. | عرض حي للمشروع الحالي/سياقه/ملفاته/آخر مهمة/الموافقات/الدليل، مع empty/error/loading states حقيقية. |
| Plan Board فوق الدردشة | يجعل التنفيذ مرئياً ويمنع فصل chat عن المهمة. | عرض `DurableTask`/run/step والأحداث الحقيقية، وفتح Trust/Evidence بدقة. |
| دورة chat للمشروع | هي نقطة دخول المستخدم اليومية. | rename/pin/archive/delete وربط المشروع؛ إلغاء generation؛ مشاركة منقحة فقط. |
| Preferences explicit | يحقق تخصيصاً إنسانياً بلا profiling خفي. | عقد تخزين محلي/consent/export/delete للغة والأسلوب واللون والأهداف؛ لا استنتاج تلقائي حساس. |
| اقتراح الخطوة التالية | يساعد تكرار الاستخدام بعد انتهاء المهمة. | rule-based، project-owned، قابل للرفض، لا ينفذ ولا يتطلب LLM أو قراءة بيانات غير مصرح بها. |

| يؤجل عمداً | سبب التأجيل |
|---|---|
| VNC، التحكم في Windows، Cloud Computer، Desktop Mesh | ليس لها target identity/ownership/consent/recovery متحقق بعد؛ تضيف خطراً قبل إثبات الحلقة الأساسية. |
| Marketplace، Billing، فرق، دعوات، نمو/SEO | لا تعالج Job-to-be-Done الأول ولا توجد أدلة استعمال متكرر أو متطلبات قانونية/تشغيلية مكتملة. |
| Browser DOM، login، uploads، payments، terminal agent replay | تتطلب نماذج user takeover/idempotency وأدلة جهاز/مزود مستقلة. |
| “ذاكرة شخصية” مبنية على استنتاج العمر/المهنة أو السلوك | تخالف مبدأ التفضيلات الصريحة وقابلية التحكم في البيانات. |

## مقاييس تحقق الفرضية

لا تُقاس القيمة بعدد الشاشات أو عدد commits. تنفذ مرحلة alpha بعد توصيل الرحلة الأساسية على جهاز حقيقي، وتشمل مستخدمين متطوعين موافقين من الشريحة المحددة.

| المقياس | ما يقاس | علامة نجاح مبدئية |
|---|---|---|
| Time to re-orient | زمن فهم المستخدم لوضع مشروع عاد إليه. | تحسن ملموس مقارنة بمحادثة بلا Project Home؛ يعاير الرقم بعد أول 5 جلسات. |
| Context trust | نسبة المستخدمين الذين يستطيعون وصف مصدر السياق/الذاكرة ولماذا ظهر. | لا لبس جوهري حول النطاق أو سبب الظهور. |
| Approval comprehension | نسبة من يشرحون الأثر قبل الضغط على Allow. | لا موافقات مفاجئة؛ كل قرار يعرض فعلًا محدداً ومالكاً واضحاً. |
| Weekly return | عودة لاستخدام مشروع حقيقي في أسبوع ثانٍ. | قرار retention بعد عينة صغيرة، لا افتراض. |
| Willingness to pay | مقابلة مدفوعة/تعهد تجريبي/استخدام beta مدفوع وفق القانون. | إشارة دفع من العميل المستهدف، لا إعجاب عام أو تحميل مجاني. |

## برنامج أبحاث العميل

1. كتابة script مقابلة يطلب من المشارك أن يعرض كيف يعود لمشروع مهجور، كيف يحدد آخر قرار، وأين يخاف من agent أو السحابة.
2. اختيار 8–15 مشاركاً من **شريحة واحدة** وعدم خلط الطلاب والمطورين وأصحاب الأعمال في مقياس واحد.
3. تنفيذ session مراقبة مهمة باستخدام build موثق، مع موافقة واعية، وعدم إرسال محتوى مشاريعهم إلى أي طرف خارج ما يختارونه.
4. تدوين سلوك المهمة، لا الرأي فقط: وقت العثور على المشروع، قدرة شرح السياق، الأخطاء، الثقة في approval، والرغبة في العودة.
5. تقرير قرار: الاستمرار في persona أو تعديلها أو إيقاف مسار الميزة. لا يفتح billing قبل نتيجة تكرار/دفع حقيقية.

## حدود الحقيقة التجارية

لا يمكن اشتقاق قيمة بيع أو دخل 10,000 دولار من الأسطر البرمجية أو ساعات العمل أو المقارنة بالمنصات الكبيرة. ترتفع قيمة AIRI القابلة للعرض على مشترٍ أو مستثمر عندما توجد: IP مملوك ووثائق معمارية، build قابل لإعادة الإنتاج، privacy/security evidence، استخدام متكرر موثق، تدفقات تحويل/دفع، retention، وحقوق قانونية واضحة للبرمجيات والأصول والاعتمادات. يمكن لهذه الخطة بناء الأدلة التقنية والمنتج؛ لا يمكنها ضمان سعر أو مشترٍ أو إيراد.
