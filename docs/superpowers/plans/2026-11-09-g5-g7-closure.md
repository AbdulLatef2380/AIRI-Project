# G-5/G-6/G-7 Closure Implementation Plan

> **For agentic workers:** تنفيذ الخطة داخل جلسة AIRI الحالية، مع اختبار كل عقد مستقل قبل الانتقال للذي يليه.

**Goal:** جعل lifecycle المهارات ذا مصدر واحد وsnapshot version واضح، إزالة تكرار capability prompts، وبناء repair model-facing fail-closed ومحدود المحاولات.

**Architecture:** ستشارك كل المسارات `SkillRegistry` و`CustomSkillRepository` على مستوى application context، مع `SkillCatalogSnapshot` يحمل version ثابتًا لكل execution. سيصبح prompt dedupe pure policy قبل الإرسال، بينما يقرر `ModelFacingRepairContract` منطق الإصلاح من error code وmetadata لا من نص الخطأ وحده.

**Tech Stack:** Kotlin، Android SharedPreferences، coroutines، JUnit JVM.

**Spec:** `docs/audits/AIRI_REMAINING_REPAIR_PLAN_2026-11-09.md` sections G-5/G-6/G-7.

## Global Constraints

- لا تُحفظ secrets أو raw prompts أو PII في snapshots أو repair diagnostics.
- لا يجوز أن يتجاوز repair firewall أو يعيد side-effect ذي outcome غير مؤكد.
- required tools لا تُحذف بصمت بسبب context budget.
- snapshot version ثابت داخل execution ولا يتغير منتصف الطلب.

## Review Focus

- إنشاء registry/repository من ChatViewModel وPromptService وSkillService يجب أن ينتج identity مشتركة.
- تسجيل/حذف skill أثناء execution لا يغير snapshot المستخدم في نفس execution.
- structured tool schema لا يظهر معه narrative duplicate.
- invalid arguments تُصلح، auth/permission/network للكتابة تتوقف، والـrepair bounded.
- capability المطلوبة غير المكشوفة تُنتج سببًا دقيقًا لا ادعاء عدم وجودها.

### Task 3: Model-facing repair contract

**Files:**
- Create: `ModelFacingRepairContract.kt`
