# تقرير القبول الإنتاجي — AIRI

**تاريخ التحقق:** 17 أغسطس 2026
**النطاق:** شجرة العمل في فرع `architecture-refactor` المبنية فوق الالتزام البعيد `73828b26473fa68caeddbe3541c26e948492abfe`، وتشمل إصلاحات محلية قيد الحفظ.
**قرار الإطلاق:** **غير جاهز للنشر العام بعد؛ جاهز لمرحلة تحقق على جهاز وإعداد إصدار موقّع.**

> اجتازت الشجرة الحالية بوابات البناء المحلية المتاحة، لكن هذا لا يعادل اعتماد إصدار إنتاجي. لا تزال اختبارات الجهاز الفعلي والموفرات الحقيقية وترحيلات قاعدة البيانات وAAB موقّعاً شروطاً مانعة للإطلاق العام.

## 1. الملخص التنفيذي

تم التحقق محلياً من تجميع APK Debug، و`lintDebug`، واختبارات JVM، والمتَحقق الثابت الخاص بالمشروع. أنتج `:app:assembleDebug` حزمة Debug بحجم **54,791,137 بايت** وتضم المكتبة الأصلية `lib/arm64-v8a/libairi_native.so` بحجم **3,759,488 بايت**. نجح `:app:lintDebug` بلا أخطاء، ونجحت **15 من 15** اختبار JVM بلا إخفاقات أو أخطاء، ومرّ المتحقق الثابت في **25 من 25** فحصاً.

تغطي اختبارات JVM قواعد التوجيه المحلي والسحابي، التشغيل المتصل وغير المتصل، fallback المحلي، الحالة التي لا يوجد فيها fallback، التوجيه الهجين والمرئي، ورفض اختبار اتصال النموذج البعيد لرد `401`. كما تعكس الشجرة الحالية نقل مفاتيح الموفرات والنهايات المخصصة إلى التخزين المشفر، عزل اعتماد endpoint المخصص، واستعادة جلسات مساحة العمل من التخزين الدائم.

| مجال القرار | النتيجة الحالية | حد القبول |
|---|---|---|
| APK Debug والبناء المحلي | **PASS** | حزمة Debug مبنية محلياً؛ ليس دليلاً على إصدار Release. |
| lint واختبارات JVM | **PASS** | لا تغني عن instrumentation أو اختبار جهاز. |
| التوجيه والتبديل على مستوى JVM | **PASS_WITH_LIMITATION** | الاختبارات تستخدم backends وخادم HTTP محلياً، لا موفراً فعلياً. |
| استعادة المساحة ومفاتيح المزود | **PASS_WITH_LIMITATION** | سلوك المصدر بُني وفُحص؛ لا اختبار restart على جهاز. |
| قاعدة البيانات وترحيل SQLCipher | **NOT_RUNTIME_VERIFIED** | لا يجوز تفعيل التشفير قبل اختبار migration فعلي. |
| الصوت والجدولة والإتاحة وRTL المرئي | **NOT_RUNTIME_VERIFIED** | يلزم جهاز فعلي وقياسات قابلة لإعادة التشغيل. |
| إصدار Play Store موقّع | **NOT_READY** | لم يُبنَ AAB Release ولم يكتمل التوقيع أو فحصه. |

## 4. قبول وقت تشغيل النماذج والاستجابة

يثبت الاختبار الآلي الحالي قواعد التوجيه التي يمكن تشغيلها بلا جهاز. لم تُستخدم مفاتيح حقيقية، ولم يُستدعَ أي موفر خارجي، ولذلك لا يوصف أي سيناريو أدناه بأنه اختبار موفر إنتاجي.

| سيناريو | الدليل الحالي | الحكم |
|---|---|---|
| `LOCAL_ONLY` | `RoutingPolicyTest.localOnlyAlwaysSelectsLocal` | PASS على مستوى JVM. |
| `CLOUD_ONLY` متصل مع fallback | `cloudOnlyOnlineSelectsCloudThenLocalFallback` | PASS على مستوى JVM. |
| `CLOUD_ONLY` غير متصل مع fallback | `cloudOnlyOfflineWithFallbackSelectsLocalWithoutAttemptingCloud` | PASS على مستوى JVM. |
| `CLOUD_ONLY` غير متصل بلا fallback | `cloudOnlyOfflineWithoutFallbackKeepsCloudSelectionForExplicitErrorHandling` مع المعالجة الصريحة في `HybridOrchestrator` | PASS على مستوى JVM/source؛ يلزم جهاز لتأكيد الرسالة المرئية. |
| `HYBRID` متصل وتحليل عميق | `hybridAnalyticalRequestPrefersCloudWhenOnline` | PASS على مستوى JVM. |
| `HYBRID` غير متصل | `hybridOfflineSelectsOnlyLocal` | PASS على مستوى JVM. |
| طلب رؤية عند عدم قدرة النموذج المحلي | `visionRequestUsesCloudWhenLocalCannotSupportVision` | PASS على مستوى JVM. |
| اختبار endpoint مخصص | استجابات HTTP محلية 200 و401 في `RemoteModelExecutorTest` | PASS؛ يثبت قبول النجاح ورفض عدم التفويض. |
| تبديل المزود وعزل الاعتماد | مراجعة `CloudAdapterFactory` و`SecureApiKeyStore` | PASS_WITH_LIMITATION؛ لا اختبار بمفاتيح موفر حقيقية. |
| استعادة مساحة العمل بعد restart | مراجعة `WorkspaceRuntime` وحفظ الجلسات الدائم | PASS_WITH_LIMITATION؛ لا اختبار Android restart. |

يمنع التصميم الحالي توريث مفتاح endpoint سابق إلى endpoint مخصص بلا اعتماد، وينقل مفاتيح النماذج البعيدة والموفرات المضمنة من التفضيلات النصية القديمة إلى المخزن الآمن. يجب تأكيد ذلك بتجربة تبديل مزودين فعليين ومراجعة بيانات التطبيق على جهاز نظيف قبل التسويق كضمان أمني مكتمل.

## 5. قاعدة البيانات والذاكرة والمشاريع

تطبق الذاكرة سياسة قبول تستبعد المحتوى الحساس والعابر وغير المناسب للحفظ، وتقيّد البحث المتجهي بالجلسة. كما يحتفظ تطبيع النص العربي بالرموز ويعالج صوراً شائعة من الحروف والتشكيل. تثبت اختبارات JVM سياسة القبول والتطبيع، ويؤكد المتحقق الثابت أن حذف الجلسة يحذف رسائلها وذاكرتها الصريحة.

تستعيد `WorkspaceRuntime` معلومات الجلسة المحفوظة وartifacts عند التهيئة، مع معالجة فشل الاستعادة بشكل صريح. لا يزال اختبار إدخال/ترقية Room على جهاز، واسترجاع مشروع بعد قتل العملية، واختبار سعة ذاكرة طويلة الأمد، مطلوباً قبل إغلاق المخاطر التشغيلية.

**الحكم:** **PASS_WITH_LIMITATION** للمصدر والبناء المحلي؛ **NOT_RUNTIME_VERIFIED** لترحيلات قاعدة البيانات والاستعادة على جهاز.

## 6. الواجهة والصوت والمهام والخدمات الخارجية

توجد حواجز إلغاء التوليد، اختصارات المهارة `/` والمعرفة `@`، مهام WorkManager ذات أسماء فريدة وحالات محفوظة، وقيود على تكرار كلمة التنبيه. صحح lint حراسة إذن `RECORD_AUDIO` وتسجيل receiver وتوافق API 26 لمطابقة اتجاه العربية، وأضيف إعلان الكاميرا الاختياري كي لا يمنع التثبيت على أجهزة بلا كاميرا.

هذه النتائج لا تثبت صحة تجربة الاستخدام. لا تتوافر في البيئة الحالية ميكروفون أو جهاز Android أو موفر نموذج بإعداد صالح أو سيناريو Doze. لذلك تبقى الصوت، TTS/STT العربي، الإشعارات والجدولة، RTL المرئي، TalkBack، Firebase، OAuth، البث ورفع المرفقات **غير متحققة وقت التشغيل**.

## 7. الأمان والخصوصية

يعطل التطبيق النسخ الاحتياطي، ويستخدم `FileProvider` غير مصدّر، ويقيّد الخدمات الداخلية. تحافظ السجلات في المسارات المعدلة على نوع الفشل أو طول المحتوى بدلاً من نص رسالة الموفر الخام. تُخزّن مفاتيح الموفرات في المخزن الآمن بعد نقل أحادي الاتجاه من القيم القديمة، وتستخدم النهايات المخصصة معرفاً مهشماً للمفتاح المخزّن.

**الحكم:** **PASS_WITH_LIMITATION**. يلزم قبل الإصدار فحص AAB موقّع، مراجعة تبعيات، اختبار deep links وOAuth وFileProvider، ومراجعة إعدادات Firebase وData Safety.

## 9. القرار النهائي

**غير جاهز للنشر العام حالياً، لكنه لم يعد محجوباً على مستوى البناء المحلي.**

يوجد الآن APK Debug صالح للبناء، وlint نظيف، واختبارات JVM خضراء، ودليل ثابت على الإصلاحات المركزية. لا يجوز مع ذلك تمثيل النسخة كمنتج Play Store جاهز لأن `targetSdk` الحالي 34 لا يطابق متطلب API 36 الوشيك، ولأن Release الموقّع والاختبارات على جهاز ومزودات النماذج الحقيقية وترحيل Room والقياسات وتجربة الوصول لم تُعتمد بعد. بعد إغلاق عناصر P0 أعلاه، يمكن إعادة التصنيف إلى **جاهز لاختبار تجريبي محدود**؛ ولا يُوصى بإصدار عام قبل إغلاق عناصر P1 الحرجة.
