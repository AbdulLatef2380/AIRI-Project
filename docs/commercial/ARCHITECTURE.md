# AIRI Core Architecture for Commercial Review

AIRI يفصل واجهة Android عن تنفيذ الوكيل، والتوجيه بين النماذج، والذاكرة، والمهارات/الموصلات، وخدمات Android. يسمح هذا التقسيم لفريق جديد بتغيير العلامة أو المزود أو نوع المرفق من دون إعادة كتابة نواة المحادثة أو التخزين.

## ما هو قابل لإعادة الاستخدام

| طبقة | قيمة التكامل أو الترخيص |
|---|---|
| التنفيذ والإلغاء | تشغيل وكيل بحالة تنفيذ حقيقية وحاجز generation ضد callbacks القديمة. |
| توجيه النماذج | مسارات محلية/سحابية خلف حدود backends وسجل نماذج. |
| الذاكرة وRAG | admission مقصود، عزل جلسة، وprompt boundary للبيانات غير الموثوقة. |
| المهارات والموصلات | فصل workflow عن data/tool access كي لا يتحول التكامل إلى صلاحية ضمنية. |
| صوت ومرفقات وجدولة | خدمات Android يمكن تكوينها كميزات منتج لا كاعتماد واجهة منفصل. |

المرجع الفني الكامل: [Architecture Overview](../architecture/OVERVIEW.md).

## قابلية الاستمرار

المستودع يتضمن Room schemas وmigrations وCI واختبارات JVM وinstrumentation وفاحصات مصدر وأمان. الملفات كبيرة الحجم المحددة بواسطة `scripts/airi_core_health.py` هي مرشحات refactor تحت اختبار، وليست سبباً لتغيير معماري جماعي غير محكوم.

## حدود صريحة

لا توجد SDK عامة أو backend متعدد المستأجرين حالياً. المشتري الذي يحتاج API خارجية أو Teams/SSO يضيفها فوق هذه الحدود بدلاً من افتراض أنها مكتملة في تطبيق Android.
